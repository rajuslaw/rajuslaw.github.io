Agentic Automation Tool Use + Routing Service Accounts + Vault

Solution Center Automation

A multi-system automation agent that reads employee service requests, understands intent, routes to the right backend, executes the action, and sends a professional response.

Role Technical Lead / Principal
Domain Employee Service Desk
Pattern Agentic Automation
Execution API-first + UI fallback

01 — Problem

Routine service requests were consuming human effort across multiple systems.

Employees used a shared service desk to request routine operational tasks such as travel and expense requests, corporate-card balance lookups, and invoice queries.

Each request required a person to read the email, identify the right system, log in, retrieve or submit information, and write a response. The workflow was repetitive and spread across different enterprise applications.

Goal

Absorb routine requests end to end and escalate exceptions instead of requiring a human to execute every standard request.

The architecture separates language understanding and routing from the deterministic action layer, allowing the same agent pattern to work across multiple enterprise systems.

03 — The Four Stages

Each stage has a clear responsibility.

01

Email reading & intent detection

Read inbound mail through IMAP or Microsoft Graph. Detect the request intent and extract entities such as user, request date, and card or reference IDs.

02

Decision routing

Map the detected intent to the target backend. Common requests use classifier or embedding-based routing, while ambiguous cases can use LLM function-calling. The intent-to-system mapping is stored explicitly.

03

Action execution across systems

Prefer APIs using OAuth2 or token authentication and REST calls. Where a system has no suitable API, use headless browser automation with Playwright as the fallback.

04

Response generation & reply

Convert the structured execution result into a natural, professional email and send it through SMTP or Microsoft Graph.

04 — Security & Access

Enterprise access is part of the architecture, not an afterthought.

An automation agent operating inside real enterprise systems needs controlled, auditable access to those systems.

01

Service identities

Use service accounts or delegated access instead of personal credentials.

02

Strong authentication

Use OAuth2 tokens or SSO integration for backend access.

03

Vaulted secrets

Store credentials in a managed vault, never directly in application code.

04

Auditable automation

Prefer headless and traceable automation paths for operational actions.

06 — Why Agentic

This is more than a single LLM prompt.

The system forms a multi-step agent loop: it perceives by reading email, decides through intent detection and routing, acts through tools across enterprise systems, and communicates by composing and sending a response.

Perceive Read and interpret the request
Decide Select intent, system and action
Act Invoke APIs or browser automation
Communicate Return a structured result as a professional reply
Key architectural idea

LLMs handle language and ambiguity; explicit routing, tools, access controls, and validation govern what the system actually does.

07 — Design FAQ

Questions I would expect in an architecture review.

How does the agent act when a system has no API?

APIs are preferred. For UI-only systems, headless browser automation with Playwright can log in using a service account, navigate the application, read data, and submit forms.

How are credentials protected?

Service accounts or delegated access are used with OAuth2 or SSO, while secrets are stored in a managed vault rather than in code.

What prevents a misclassified request from taking the wrong action?

Routing combines fast classification with LLM function-calling for ambiguous cases. Responses are validated before sending, and low-confidence or exceptional requests are escalated instead of being actioned blindly.

Why is API-first important?

APIs provide a more scalable and robust execution path. UI automation is useful when no API exists, but it is more brittle and harder to maintain.
